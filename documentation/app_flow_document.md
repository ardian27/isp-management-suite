# App Flow Document for Integrated ISP Management Suite

## Onboarding and Sign-In/Sign-Up

When a new user arrives, they land on the sign-in page by navigating to the application URL. On that page, they see an option to sign in or create a new account. To sign up, the user clicks the sign-up link and is taken to a registration form where they enter their name, email address, and password. After submitting the form, the system creates their account and logs them in automatically, redirecting them to the dashboard. If the user already has an account, they simply enter their email and password on the sign-in page and click the button to authenticate. In case a user forgets their password, they click the “Forgot Password” link which takes them to a page where they provide their email address. The system sends them a password reset link to that address. When they click the link, they land on the password reset page where they choose a new password and submit. Upon successful reset, they are taken back to the sign-in page. At any time when logged in, the user can sign out by opening the user menu in the header and selecting the sign-out option, which ends the session and returns them to the sign-in screen.

## Main Dashboard or Home Page

After logging in, the user arrives at the main dashboard located at the `/dashboard` route. The page features a vertical sidebar on the left with navigation links for Customers, Billing, Support, CRM, Inventory, and Settings. At the top of the page is a header bar displaying the application logo on the left and a user avatar on the right. The central area of the dashboard shows an interactive revenue chart, a set of metric cards indicating counts of active customers, isolated customers, open tickets, and outstanding invoices, followed by a dynamic data table listing recent activity or prioritized items. Each chart and card widget is clickable, taking the user to the relevant page section for more detail. The sidebar link for Customers anchors the view to the customer overview. The Billing link scrolls or navigates to the invoice list. Support and CRM links work similarly. Clicking the Settings link replaces the main content with various configuration pages. This unified view gives the user a clear starting point to move anywhere in the application.

## Detailed Feature Flows and Page Transitions

### Customer Management Flow

When the user clicks on Customers in the sidebar, they arrive at `/dashboard/customers`. Here they see a table listing every customer in the system. Above the table is a button labeled “New Customer.” Clicking it opens a form in a modal or on a separate page where the user enters the customer’s personal information, selects a service package, and confirms. Submitting this form calls the `/api/customers` endpoint which saves the record in the database. After submission, the modal closes and the table refreshes to show the new customer. To view or edit a specific customer, the user clicks the customer’s row in the table, which navigates to `/dashboard/customers/[id]`. On that detail page they see tabs for Profile, Services, Invoices, and Tickets. Under Services they can provision a service by clicking “Add Service.” A small form appears where they choose a package and submit. Behind the scenes an API call to `/api/mikrotik/…` runs the provisioning logic and a record is created in the services table. Once complete, the service appears in the list and the user can see real-time status.

### Billing and Invoicing Flow

Selecting Billing in the sidebar takes the user to `/dashboard/billing/invoices`. They see a list of all invoices with their status and due dates. Above the list is a button called “Generate Invoice.” Clicking it triggers a request to `/api/billing/generate`, which creates invoices for all customers with usage data. The page then reloads to display the new entries. Clicking on any invoice navigates to `/dashboard/billing/invoices/[id]` where the user can view details, download a PDF, or send a manual reminder email. When a customer pays, the payment gateway sends a webhook to `/api/payment/webhook`, which updates the invoice status to paid in the database and triggers a notification. The dashboard then reflects the updated invoice status. Scheduled tasks also run daily to generate invoices and isolate overdue customers automatically.

### Support Ticket Flow

Clicking Support leads to `/dashboard/support/tickets`, showing a list of open and closed tickets. A “New Ticket” button brings up a form to capture ticket details such as customer, issue description, and priority. Submitting this form posts to `/api/tickets` and the table updates. To work on a ticket, the user clicks its row, which opens `/dashboard/support/tickets/[id]`. Here they find full details, can add comments, change status, or assign it to a technician. All updates are saved through API calls and the ticket list updates accordingly.

### PPPoE Provisioning and Isolation Automation Flow

Under Settings there is a Mikrotik configuration page at `/dashboard/settings/mikrotik`. The admin enters the router’s IP address, API username, and password, then saves. Those credentials are stored securely. A daily scheduled job on Vercel calls `/api/billing/check-due-invoices`. This endpoint queries unpaid invoices past their due date using Drizzle ORM and for each overdue record calls the service in `lib/mikrotik.ts`. That service connects to the router and changes the customer’s PPPoE profile to “Isolated.” After isolation, the system triggers the notification service in `lib/notifications.ts` to send a WhatsApp or Telegram message reminding the customer to pay. Administrators can also isolate or restore a single customer manually by visiting the customer’s services tab and clicking “Isolate” or “Restore.”

### CRM and Sales Flow

When CRM is selected, the user sees two links: Leads and Coverage Map. Clicking Leads navigates to `/dashboard/crm/leads` where a table lists all sales leads. A “New Lead” button opens a form to add lead details. Once saved to `/api/leads`, the table refreshes. Leads can be edited or deleted inline. Clicking Coverage Map opens `/dashboard/crm/coverage-map` which displays an interactive map. The user can draw coverage zones, name them, and save to `/api/coverage-zones`. Saved zones appear on load, giving a visual overview of service areas.

### Inventory and Asset Management Flow

Selecting Inventory shows `/dashboard/inventory/stock`, a page listing all stocked items such as routers and cables. The user can add stock by clicking “Add Item” which opens a form. Submission posts to `/api/inventory` and the new item appears in the list. Each item row includes controls to adjust quantity or mark as used, updating via API calls and reflecting changes immediately.

## Settings and Account Management

In the Settings section accessible from the sidebar, there are Pages for Users, Service Packages, and Notifications. On the Users page at `/dashboard/settings/users`, administrators see a list of all user accounts and their assigned roles. They can click “Add User” to create new accounts, choosing roles like Admin, Finance, Technician, or Sales. Edits save via the `/api/users` endpoint. The Service Packages page at `/dashboard/settings/packages` allows admins to define or modify the offerings customers can subscribe to. All changes are submitted to `/api/packages`. Under Notifications there is a page at `/dashboard/settings/notifications` where users set their preferences for email and messaging updates. Here they can toggle reminders, alerts, and webhook integrations. Each preference change calls `/api/user-preferences` and updates their profile. From any settings page, the user clicks the breadcrumb or sidebar link to return to the main dashboard or navigate to another section.

## Error States and Alternate Paths

If a user enters incorrect credentials on sign-in, they see a clear message above the form indicating invalid email or password. If a sign-up attempt uses an email already in the system, they receive an error explaining the duplicate. During password reset, submitting an unknown email shows a warning that the address is not registered. Any form with invalid data highlights the problem field and provides a short description of the expected input. If the application loses connectivity during an API call, a banner appears at the top stating the issue and retrying can be done by refreshing the page or clicking a retry button. Attempting to access a page without proper permissions redirects the user to a “Not Authorized” view with a link back to the dashboard. When the user navigates to an undefined route, they are shown a friendly 404 page that offers a link back to the home dashboard. Server-side errors display a generic message and log the details in the central logging service, prompting users to try again later.

## Conclusion and Overall App Journey

From the moment a user lands on the sign-in page through to daily operations on the dashboard, the application guides them with clear flows. A new user registers, verifies credentials, and arrives at a dynamic home page showing vital metrics. From there they can manage customers, billing, support tickets, CRM leads, and inventory by clicking the sidebar. Settings let them configure account details, user roles, service packages, and notifications. Throughout, meaningful success and error messages keep the user informed, and scheduled jobs automate tasks like invoicing and PPPoE isolation. At the end of each day, users are empowered to review revenue trends, respond to tickets, and adjust operational parameters, all within a cohesive, secure experience.
